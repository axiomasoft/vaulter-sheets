# Закрытый пакет электронных таблиц

Получатель — FlexCrm или Edufy. В публичном FlexCms остаются документы и одиночное сохранение. Этот план покрывает извлечение существующего типа, первую нативную книгу, операции агента, браузерный редактор и опциональную связь с Tiptap. Исходная точка — `b230f6e27`. Форматы и внешние API движков проверяем на версиях из отчётов. Решение о вводе конкретного движка в продукт принимает команда после прогона вертикального сценария.

## Владелец книги и граница вычислений

Узел, права, история и файлы остаются у Drive/Documents/Media. В первой версии работает обычный режим с проверкой прочитанной версии при сохранении. Способ сериализации долгоживущего содержимого выбирает пакет Sheets. Начинаем со снимка, полученного штатным методом движка, с версией формата, перечнем необходимых плагинов и ресурсов. Для незнакомого обязательного ресурса редактирование должно закончиться диагностикой до публикации изменённой версии. Полученные после чтения адреса и вычисленные значения сами по себе не являются полным снимком.

| Операция в адаптере Sheets | Обязательное поведение |
| --- | --- |
| Открыть / получить описание | Проверить доступ пользователя к узлу. Отдать стабильные ID листов, их отображаемые имена, именованные диапазоны и версию. У движка запросить поддерживаемые возможности и проверить совместимость снимка |
| Прочитать диапазон | Принимать лист, прямоугольник, нужные поля и предел ответа. Различать литерал, исходную формулу, сырое вычисленное значение, формат отображения, ошибку и версию завершённого расчёта. При отставании возвращать состояние ожидания или пересчитывать через авторитетный runtime |
| Применить изменение | Доменный обработчик получает проверенный контекст пользователя, ID книги, ожидаемую версию, семантику выделения, типизированные операции и ключ команды. Формула задаётся отдельным типом. Обновление диапазона, вставка строки и изменения формул проходят через публичные команды движка. Сохранять правку и её квитанцию согласованно; повтор того же намерения восстанавливает исход, повтор того же ключа с изменённым содержанием отклоняется |
| Проверить результат | Сравнивать идентичность затронутых строк, реальные ссылки и значения в отдельных ячейках после расчёта на нужной версии. Возвращать небольшой диапазон и квитанцию. Выдача ранее сохранённого результата повторно проверяет права |
| Сохранить / восстановить | Сохранять представление, включающее ресурсы плагинов. Web и Node открывают один формат. При восстановлении создаётся новое поколение, истёкшие контексты записи и результаты запоздалого пересчёта предыдущего поколения отбрасываются |

Фиксированный список строк означает, что команда обрабатывает выбранные логические записи. Для операции по актуальному составу строки определяются при подготовке. В контракте `sheet.fill_formula@1` режим `current_rows` завершает изменившееся поручение ошибкой `scope_changed`. Для нового состава требуются новое чтение, предложение и новый ключ. Для `fixed_members` агент может передать в селекторе чтения `row_ids` двух выбранных строк. Сервер проверяет полный охват явно запрошенных ID, права и исходные зависимости перед применением формул. При перестановке сохранная целевая строка определяется по ID. Адрес C3 после структурного изменения может занять другая запись.

Для первого обычного редактора снимка достаточно условной записи с проверкой версии. Публиковать `sheet.fill_formula@1` в AI-каталоге можно после проверки стабильных ID таблицы, строк и колонок, обеих семантик состава и повторов по квитанции. Если движок даёт только координаты, устойчивую идентичность реализует Sheets.

Внутреннюю схему JS SDK нельзя непосредственно публиковать как контракт AI. Табличный адаптер AI формирует `sheet.fill_formula@1`, привязывает его к выбранной области и вызывает Sheets. Список действий пользователя и агента проверяется одним серверным путём. Интерфейс Vue обновляется через принятую версию, в том числе если агент завершил задание после закрытия вкладки.

## Прототип движка и контрольный пример

[Вектор книги](../examples/workbook.json) задаёт вход, последовательность команд, инъекцию ошибочного кэша и ожидаемые значения независимо от библиотеки. Версии 1–3 — логические позиции тестового адаптера. Для конкретного протокола их отображают на его реальные ревизии. Формулы сравниваются с нормализацией разделителей и префиксов имён, при этом диапазон и относительность ссылок обязаны совпадать.

1. Собрать одинаковую книгу в браузере и отдельном процессе Node на согласованных версиях пакетов Univer. Зафиксировать версию, набор плагинов, формат снимка и режим вычислителя. Ожидаемый итог до изменения цены — 35. После изменения C3 на 7 — 41.
2. Вставить строку в Detail перед строкой 2. Проверить, что яблоки и цена 10 остались вместе, цена груш 7 переехала в C4, формулы D3/D4 и межлистовая сумма ссылаются на новые адреса. Повтор первой команды по ключу возвращает её старую квитанцию. Новая команда по устаревшей C3 должна вернуть конфликт до записи.
3. Завершить процесс. В копию тестового снимка подставить заведомо ложный кэш 999 для итога. Открыть в новом процессе при той же версии; до подтверждённого пересчёта эту величину нельзя отдать как проверенный результат. Выполнить полный пересчёт и дождаться завершения. Отдельно проверить исходную формулу, числовое 41 и строку отображения согласно локали.
4. Расширить корпус условным форматированием, неизвестным обязательным ресурсом плагина, именованным диапазоном, merged cells, стилями, валидацией и датами Excel 1900/1904. Проверить сохранность после простой записи и отдельно после структурной команды. Исходный XLSX хранить неизменяемым; при частичном импорте вернуть перечень потерь. Заявление о поддержке XLSX требует проверки повторного открытия в целевом Excel.
5. Ресурс вне профиля отвергается до открытия движка (`unsupported_content`, `reason: unknown_resource`), а ресурс, который `save()` потерял, — до записи (`unsupported_content`, `reason: resource_lost`). В обоих случаях снимок и версия не меняются. Шаги 1–3 и это правило проверены образцом `workbook-operation` (сценарии A0–A8, S2) и контрактным гейтом `scripts/ci/workbook-contract.sh`. Формат обмена — [wire-контракт](runtime-wire-v1.md).

В 4.1 сравнить кандидатов на общем корпусе. **Univer Sheets OSS 1.5.2 (Apache-2.0)** обеспечивает основной коммерчески чистый профиль Vue/Node. Для сверки вычислений и обмена взять **IronCalc 0.9.1 (MIT/Apache-2.0)**; `Handsontable 18.1.2 + HyperFormula 3.5.0` допустимы **только как офлайн-ориентир бенчмарка и запрещены в production по лицензии** ([лицензионный стоп-кран](engineering-standards.md#2-постоянные-архитектурные-запреты-стоп-краны-ci)). В результатах указывать фактически запущенные версии. Проверять корректность формул и обмена, чтения, память и задержку от ввода до сохранённого результата при холодном процессе. Glide Data Grid и RevoGrid рассматриваются для отдельного экрана записей CRM. [Критерии выбора в задаче 4.1](../phases/04-sheets.md)

В headless-композиции Univer 1.5.2 сохранение может удалить неизвестный ресурс, а вставка сдвигает именованный диапазон, но оставляет правило условного форматирования на D2:D3 вместо D3:D4. Владелец до записи сверяет ресурсы книги и операцию с профилем. Если обязательный ресурс потеряется или правило останется на старых ячейках, вернуть отказ и сохранить исходный снимок. Версии и плагины фиксируются для каждого прогона. [Проверка в отдельных Node-процессах](../bench/probes/univer-headless.sh)

## Браузер, совместная работа и Tiptap

В браузерном стенде Vue 3.5.39 и Univer 1.5.2 ввести 7 в Detail!C3 и нажать Enter. Проверить D3 = 21 и значение 41.00 на canvas после открытия Summary. После вставки строки проверить перенос формул, закрыть и освободить редактор. Приёмка 4.2 дополнительно включает сохранение через PHP и чтение новым браузером. [Браузерный стенд](../bench/probes/sheets-browser/README.md)

- При открытии книги закрытый Vue-компонент лениво загружает движок, монтирует один экземпляр и удаляет подписки и экземпляр при закрытии. Обычное изменение данных сохраняет фокус и selection. Контракт загрузки текущего узла и статус сохранения видны при ошибке и конфликте.
- Пользователь выбирает D2:D3. Хост получает устойчивые ID этих строк для селектора `sheet_table.row_ids`. Пользователь просит рассчитать «Факт − План». Пока сервер считает, пишет «проверено» в E2. При ответе D2/D3 дают 10 и −10; в строке формул у D2 видна `=C2-B2`. E2 сохраняется, входящий пакет не отправляется серверу обратно, Ctrl+Z отменяет последнюю правку пользователя согласно локальной истории. Проверить и после закрытия/повторного открытия вкладки.
- Системный clipboard: вставка 100×100 отменяется одним действием. Отдельно проверить копирование TSV/HTML, русскую раскладку, навигацию стрелками, правильное чтение координат и значений экранным диктором. Измерить начало ввода, long tasks и остаточную память после 20 открытий, с одинаковым набором 100 тыс. заполненных ячеек и 10 тыс. формул.
- Для одновременных структурных изменений у книги должен быть один авторитетный протокол, последовательность принятия команд и способ догнать изменения после отключения. Сравнить конфликт «вставка строки + изменение прежней C3» на обоих порядках доставки с повтором после разрыва. Уточнить доставку записи агента в живой браузер и восстановление после сбоя. До прохождения теста продукт предлагает снимок с проверкой версии; правки разных ячеек двумя пользователями при этом не конфликтуют (`rebase_cells`). Механизм Yjs для текста подключением Sheets не включается. В `6.1` зафиксирован **собственный Zero-Pro серверный журнал команд** (`protocol = 'univer-sheets/1'`) поверх Apache-2.0 ядра Univer и **единого PHP-движка `vaulter-collaboration`** (коммерческий `@univerjs-pro/collaboration` запрещён; см. [6.1](implementation/sheets.md#61-и-62-независимые-дополнения)).
- Встраивание в текст начать со ссылки на книгу, стабильный ID листа, диапазон и выбранную семантику перемещения. При открытии и формировании превью сервер проверяет права на источник. Читатель урока без доступа к книге получает нейтральную заглушку без названий и содержимого ячеек. Для удалённого листа виден статус недоступности. При отключённом расширении ссылка выдерживает сохранение и повторное открытие. В экспорт разрешаем только согласованный тип представления с проверкой прав в момент экспорта.

## Приёмка изменения

Исполнитель предоставляет для каждой проверки исходный файл или описание фикстуры, версию сборки, фактические команды и результаты. Ревьюер независимо повторяет установку базового и расширенного потребителей из собранных артефактов и сверяет структуру книги, обе формулы и квитанции. Приложить вывод команды, которая сравнивает формулы, значения и ID строк. [Формат приёмки](../acceptance.md)
